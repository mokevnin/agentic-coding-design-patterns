# Фразы для AGENTS.md

Здесь собраны правила для [памяти проекта](claude-md-memory.md), которые помогают агенту принимать решения при выборе реализации. Подбирайте их под проект и добавляйте только те, которые меняют поведение агента в нужную сторону.

За основу взят список Marcos Hernanz. Две последние формулировки добавил [Кирилл Мокевнин](https://x.com/mokevnin/status/2083152573679173830).

Этот блок можно скопировать в файл памяти проекта.

```markdown
# AGENTS.md
- Do not preserve backward compatibility.
- Choose the simplest implementation that fully meets the current requirements.
- Prefer established, well-maintained libraries over custom implementations.
- Fix the cause, not the symptom.
- Suggest best practices, even if they may require refactoring.
```

Правила приведены на английском. При желании переведите их на язык команды. Как объясняет глава [«Память проекта»](claude-md-memory.md), файл _направляет_ поведение агента, но не гарантирует соблюдения правил. Держите список коротким, чтобы он не превратился в [раздутую память](bloated-claude-md.md).

## Do not preserve backward compatibility

_Не тащи обратную совместимость._

По умолчанию агент может оставлять старые поля «на всякий случай» и добавлять слои совместимости вокруг изменения. Во внутреннем модуле, который целиком контролирует одна команда, такие слои часто создают лишнюю работу. Правило разрешает агенту удалить старый интерфейс и обновить его вызовы в той же правке.

Правило подходит для приложений и внутренних модулей, если команда контролирует их потребителей. Для публичной библиотеки или внешнего API совместимость входит в контракт с пользователями, поэтому там нужно явно требовать её сохранения.

## Choose the simplest implementation that fully meets the current requirements

_Выбирай простейшую реализацию, полностью закрывающую текущие требования._

Агент может заложить точки расширения под задачи, которых ещё нет. Правило возвращает его к принципу YAGNI и текущим требованиям. Например, если нужен один формат экспорта, универсальная система плагинов добавит код, который пока нечем обосновать. Слово _fully_ требует реализовать весь согласованный сценарий, включая обработку ошибок.

Та же проблема возникает при [преждевременной спецификации](premature-specification.md), когда команда выбирает устройство решения до того, как разобралась с задачей.

## Prefer established, well-maintained libraries over custom implementations

_Предпочитай зрелые, поддерживаемые библиотеки самописным реализациям._

Агент может написать собственный парсер дат, который проходит простой пример и ошибается на переходе часового пояса. У зрелой библиотеки такие случаи уже могут быть разобраны и покрыты тестами. Правило побуждает проверить готовые решения и сократить объём кода, который команда будет сопровождать сама.

Перед выбором библиотеки проверьте состояние репозитория, релизы и поддержку нужных сценариев. Заброшенная зависимость может потребовать больше работы, чем собственная реализация.

## Fix the cause, not the symptom

_Найди и исправь причину ошибки._

Столкнувшись с падающим тестом, агент может добавить `try/catch`, после которого симптом исчезнет. Если ошибка возникла из-за неожиданного `null`, такое исправление оставит источник некорректного значения на месте. Правило требует выяснить, откуда пришёл `null` и какой контракт нарушен.

Правило можно сочетать с [рефлексией](reflection.md). Перед правкой агент объясняет причину сбоя, и вы проверяете, устраняет ли предложенное изменение эту причину.

## Suggest best practices, even if they may require refactoring

_Предлагай лучшие практики, даже если они могут потребовать рефакторинга._

Агент, который стремится к минимальному диффу, может повторить недостаток соседнего кода. Правило разрешает предложить рефакторинг и объяснить, как он поможет решить задачу. Человек оценивает пользу и согласует объём работы.

Агент может предлагать рефакторинг слишком часто. Сочетайте это правило с требованием выбирать простейшую реализацию и сначала устанавливать причину проблемы.
