# Полезные ссылки

Подборка ссылок на инструменты [спеко-ориентированной разработки](spec-driven-development.md), внешнее сравнение, которое помогает выбрать подходящий, и сборники практик работы с агентами.

## Инструменты, разобранные в книге

- [OpenSpec](openspec.md). Официальный сайт [openspec.dev](https://openspec.dev/) и [репозиторий](https://github.com/Fission-AI/OpenSpec).
- [Superpowers](superpowers.md). Исходный код и инструкции доступны в [репозитории](https://github.com/obra/superpowers).
- [Скиллы Мэтта Покока](matt-pocock-skills.md). Набор процедур доступен в [репозитории](https://github.com/mattpocock/skills).

## Другие инструменты SDD

Следующие инструменты упоминаются в книге без отдельных обзоров.

- **GitHub Spec Kit** связывает фазы SDD отдельными командами. См. [сайт](https://speckit.org/) и [репозиторий](https://github.com/github/spec-kit).
- **Kiro** поддерживает SDD в IDE. См. [официальный сайт](https://kiro.dev/).
- **Tessl** использует спецификации при разработке. См. [официальный сайт](https://tessl.io/).
- **BMAD-Method** организует работу ролевых агентов. См. [репозиторий](https://github.com/bmad-code-org/BMAD-METHOD).
- **Spec Kitty** развивает Spec Kit с поддержкой git worktree. См. [репозиторий](https://github.com/Priivacy-ai/spec-kitty).
- **Traycer** связывает планирование, выполнение и проверку в VS Code. См. [официальный сайт](https://traycer.ai/).
- **Get Shit Done** ведёт проект по фазам: обсуждение, спецификация, план, выполнение и проверка. См. [репозиторий](https://github.com/gsd-build/get-shit-done).
- **Compound Engineering** от Every завершает каждый цикл шагом, который сохраняет усвоенное для следующих задач. См. [репозиторий](https://github.com/EveryInc/compound-engineering-plugin).
- **HumanLayer** предлагает команды для цикла исследование → план → реализация. См. [репозиторий](https://github.com/humanlayer/humanlayer).

## Сравнение инструментов

- **spec-compare** сравнивает инструменты SDD. Доступны [интерактивное сравнение](https://cameronsjo.github.io/spec-compare/) и [репозиторий исследования](https://github.com/cameronsjo/spec-compare).

## Практики работы с агентами

- **Claude Code best practices** — официальные рекомендации Anthropic. См. [документацию](https://code.claude.com/docs/en/best-practices).
- **Codex best practices** — официальные рекомендации OpenAI: постановка задачи, AGENTS.md, скиллы, ревью и типичные ошибки. См. [руководство](https://learn.chatgpt.com/guides/best-practices).
- **claude-code-best-practice** и **codex-cli-best-practice** собирают советы разработчиков инструментов и сообщества со ссылками на исходные публикации. См. репозитории [для Claude Code](https://github.com/shanraisshan/claude-code-best-practice) и [для Codex](https://github.com/shanraisshan/codex-cli-best-practice).
- **awesome-codex-cli** — каталог инструментов, скиллов и плагинов для Codex. См. [репозиторий](https://github.com/RoggeOhta/awesome-codex-cli).
