# Useful Links

A collection of links to [spec-driven development](spec-driven-development.md) tools, an external comparison that helps you pick the right one, and collections of practices for working with agents.

## Tools covered in the book

- [OpenSpec](openspec.md). The official site is [openspec.dev](https://openspec.dev/), and there is a [repository](https://github.com/Fission-AI/OpenSpec).
- [Superpowers](superpowers.md). The source code and instructions are in the [repository](https://github.com/obra/superpowers).
- [Matt Pocock's Skills](matt-pocock-skills.md). The set of procedures is in the [repository](https://github.com/mattpocock/skills).

## Other SDD tools

The following tools are mentioned in the book without dedicated reviews.

- **GitHub Spec Kit** ties the SDD phases together with separate commands. See the [site](https://speckit.org/) and the [repository](https://github.com/github/spec-kit).
- **Kiro** supports SDD in an IDE. See the [official site](https://kiro.dev/).
- **Tessl** uses specifications during development. See the [official site](https://tessl.io/).
- **BMAD-Method** organizes the work of role agents. See the [repository](https://github.com/bmad-code-org/BMAD-METHOD).
- **Spec Kitty** extends Spec Kit with git worktree support. See the [repository](https://github.com/Priivacy-ai/spec-kitty).
- **Traycer** ties planning, execution and verification together in VS Code. See the [official site](https://traycer.ai/).
- **Get Shit Done** drives a project through phases: discussion, specification, plan, execution and verification. See the [repository](https://github.com/gsd-build/get-shit-done).
- **Compound Engineering** from Every ends each cycle with a step that saves what was learned for future tasks. See the [repository](https://github.com/EveryInc/compound-engineering-plugin).
- **HumanLayer** offers commands for the research → plan → implement cycle. See the [repository](https://github.com/humanlayer/humanlayer).

## Tool comparison

- **spec-compare** compares SDD tools. There is an [interactive comparison](https://cameronsjo.github.io/spec-compare/) and the [research repository](https://github.com/cameronsjo/spec-compare).

## Practices for working with agents

- **Claude Code best practices** are Anthropic's official recommendations. See the [documentation](https://code.claude.com/docs/en/best-practices).
- **Codex best practices** are OpenAI's official recommendations: framing the task, AGENTS.md, skills, review and common mistakes. See the [guide](https://learn.chatgpt.com/guides/best-practices).
- **claude-code-best-practice** and **codex-cli-best-practice** collect tips from the tool developers and the community, with links to the original publications. See the repositories [for Claude Code](https://github.com/shanraisshan/claude-code-best-practice) and [for Codex](https://github.com/shanraisshan/codex-cli-best-practice).
- **awesome-codex-cli** is a catalog of tools, skills and plugins for Codex. See the [repository](https://github.com/RoggeOhta/awesome-codex-cli).
