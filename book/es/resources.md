# Enlaces útiles

Una colección de enlaces a herramientas de [desarrollo orientado a especificaciones](spec-driven-development.md), una comparación externa que ayuda a elegir la adecuada y recopilaciones de prácticas para trabajar con agentes.

## Herramientas analizadas en el libro

- [OpenSpec](openspec.md). El sitio oficial es [openspec.dev](https://openspec.dev/) y hay un [repositorio](https://github.com/Fission-AI/OpenSpec).
- [Superpowers](superpowers.md). El código fuente y las instrucciones están en el [repositorio](https://github.com/obra/superpowers).
- [Skills de Matt Pocock](matt-pocock-skills.md). El conjunto de procedimientos está en el [repositorio](https://github.com/mattpocock/skills).

## Otras herramientas de SDD

Las siguientes herramientas se mencionan en el libro sin reseñas propias.

- **GitHub Spec Kit** conecta las fases de SDD con comandos separados. Consulta el [sitio](https://speckit.org/) y el [repositorio](https://github.com/github/spec-kit).
- **Kiro** da soporte a SDD en un IDE. Consulta el [sitio oficial](https://kiro.dev/).
- **Tessl** usa especificaciones durante el desarrollo. Consulta el [sitio oficial](https://tessl.io/).
- **BMAD-Method** organiza el trabajo de agentes con roles. Consulta el [repositorio](https://github.com/bmad-code-org/BMAD-METHOD).
- **Spec Kitty** amplía Spec Kit con soporte para git worktree. Consulta el [repositorio](https://github.com/Priivacy-ai/spec-kitty).
- **Traycer** conecta la planificación, la ejecución y la verificación en VS Code. Consulta el [sitio oficial](https://traycer.ai/).
- **Get Shit Done** lleva el proyecto por fases: discusión, especificación, plan, ejecución y verificación. Consulta el [repositorio](https://github.com/gsd-build/get-shit-done).
- **Compound Engineering** de Every cierra cada ciclo con un paso que guarda lo aprendido para las tareas siguientes. Consulta el [repositorio](https://github.com/EveryInc/compound-engineering-plugin).
- **HumanLayer** ofrece comandos para el ciclo investigación → plan → implementación. Consulta el [repositorio](https://github.com/humanlayer/humanlayer).

## Comparación de herramientas

- **spec-compare** compara herramientas de SDD. Hay una [comparación interactiva](https://cameronsjo.github.io/spec-compare/) y el [repositorio de la investigación](https://github.com/cameronsjo/spec-compare).

## Prácticas para trabajar con agentes

- **Claude Code best practices** son las recomendaciones oficiales de Anthropic. Consulta la [documentación](https://code.claude.com/docs/en/best-practices).
- **Codex best practices** son las recomendaciones oficiales de OpenAI: planteamiento de la tarea, AGENTS.md, skills, revisión y errores típicos. Consulta la [guía](https://learn.chatgpt.com/guides/best-practices).
- **claude-code-best-practice** y **codex-cli-best-practice** recopilan consejos de los desarrolladores de las herramientas y de la comunidad, con enlaces a las publicaciones originales. Consulta los repositorios [para Claude Code](https://github.com/shanraisshan/claude-code-best-practice) y [para Codex](https://github.com/shanraisshan/codex-cli-best-practice).
- **awesome-codex-cli** es un catálogo de herramientas, skills y plugins para Codex. Consulta el [repositorio](https://github.com/RoggeOhta/awesome-codex-cli).
